Placeholder Item Concepts

D14 (decided 2026-10-23): when an item's mod is missing on a server, BSP-InventorySync shows it as a placeholder that keeps the original item inside it and turns back into it on a server with the mod. Today the placeholder is plain paper, which recipes and villager trades accept, destroying the original. Three replacements, all vanilla items that no recipe, trade, furnace or composter uses. The look is the item icon; the name and lore stay text. Pick one; the build follows with a GameTest.

Decisions

  1. Base item. A, B or C. Default: A, the barrier: its icon already reads as "not usable here", and it stands out in a full inventory.
  2. Block right-click on placeholders (placing a barrier or structure void, using up a knowledge book), whichever base is chosen. Default: yes; the player sees "This is a placeholder for a missing mod's item." on the action bar.
  3. Existing paper placeholders. They are recognised by their tag, not by the paper, so they become the new base the next time they are restored on a server without the mod. Default: nothing more to do (no conversion pass).
  4. Name and lore. Name "Missing item: <item id>" (red, italic); lore "Turns back into the item on a server with its mod. Do not craft with it." Default: keep both, with the lore's second sentence changed to "Keep it: it is the real item." since crafting is no longer possible.
  5. BSP-Core shops. A shop that buys any item would still take a placeholder, and the original would be gone. Default: ask BSP-Core (request R6) to refuse items carrying the tag bsp_inventorysync:original.

Pixel icons are drawn here from small maps to show the look in a slot; in game the items use Minecraft's own textures. Everything else about placeholders (they stack only with identical placeholders, they can be dropped, stored and traded between players, an anvil rename keeps the original inside) is unchanged by this choice.
